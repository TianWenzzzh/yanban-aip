## 这一台只修一件事：给 `no_citation` 配上分母

轮 115 的结论里有一条不体面的：护栏 R1—R4 是在 `no_citation` **一次都没开火**的池子上量的
（`g96b` 的 0/48）。0 次开火分不清"这批回复本来就没论文卡"与"闸门坏了"，
所以那条闸门的**代价其实没测过**。上一代（`measure-20260923f`）印不出卡数，看不见不等于没代价。

改了三处，其余字节与 f 代同源：

1. 逐样本行多印一个 `｜卡 N｜`（该条回复当轮拿到几张论文卡）。
2. 情景表加第 5 条：`我们实验室在做光伏功率预测…` —— g96a 量到它 10/10 都带 8 张卡，
   是这条闸门少见的稳定靶子（原 4 条里 2 条 10/10 空池）。
3. 汇总自己报分母：`带论文卡的回复 X/N`，**X < 8 时明说"读不出代价"**，
   只有 X ≥ 8 才允许把开火率读成代价。

`parse_gate_yield_lines.py` 配套：卡数字段做成可选，所以拿它复解析 f 代的旧证据仍然得
「48 条样本」并印「看不见 ≠ 没代价」（实测复解析 `g96b_gate_yield_n48.txt`，见轮 116 日志）。

## 跑法（⚠️ 参数不是总条数）

    PYTHONUTF8=1 uv run --no-project --with paramiko python 输出/scripts/run_cloud_probe.py \
        输出/scripts/probe_gate_yield_v2.py 5

命令行那个 `5` 是**每个情景的条数**，上限 = N × 情景数 × 2（闸门前后各一次采样）。
加了第 5 个情景后 `5` ⇒ 50 条上下（约 1 小时）。轮 115 我按 `48` 起，实际跑成 384 条 ≈ 6 小时，
中途杀掉重跑过一次。**起完必须先读它自报的「探针上限」那一行再走开。**
长跑边跑边写容器内边车 `/tmp/probe_gate_yield_v2.txt`，断线后用它续读。

跑完要补一步对账：容器里 `sha256sum /tmp/probe_gate_yield_v2.py` 必须等于上面钉的那条
（`run_cloud_probe.py` 是 sftp 字节上传，理论上必等；万一容器里被别的会话覆盖过，
这一步会把差异暴露出来，而不是让快照钉住一份从没跑过的代码）。
