## 工作副本与快照份的差异（一处，且只在自检层）

工作副本把自检 M 拆成了两条：`M 两条规划路径一起掐掉`（打桩**期间**断言`make_plan`/`plan_prefix` 都已换掉）+ `N 打桩还得回`。快照份只有一条合并版 M，它断言的是「装得上、还得回」，看的是**还原之后**的状态。

## 已知盲区：守卫 M7 打快照份不红（打工作副本会红）

M7 = 「只掐 `make_plan`、漏掉流式那条 `plan_prefix`」（幻影对照）。快照份的合并版 M 只在还原后取值，所以漏掐一个时它察觉不到 ⇒ 冻结当场实测：守卫→快照 7 抓 1 漏（只漏 M7），守卫→工作副本 8/8。

**为什么 g100 的读数仍然有效**：这一维由**运行时哨兵 S1** 守，而不是由自检夹具守——S1 逐条读产品调用点 `repair(plan=…)` 实收的 plan（`leak = sum(1 for r in b if r['plan'])`），任一条 B 臂回复真带规划就 RC=2 整份作废。g100 实测 S1 = 0（B 臂 12 条全无规划），S2 = 12/12 ⇒ 两臂确实只差「有没有规划」这一件事。盲区影响的是「--selfcheck 绿能不能*证明*漏掐会被抓」，不影响这一份读数。
