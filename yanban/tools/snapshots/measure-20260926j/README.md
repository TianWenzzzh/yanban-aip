# measure-20260926j：`probe_provider_supply.py` 第二版（退出码分成 0/3/5 三种，不再共用 RC=2）

改这一版的直接原因：**上一版把归因判错了**。它拿 httpx 传输层数包（P3），一旦 >4 就判
「一台体检发超过 4 包 ⇒ 它自己在刷配额 ⇒ 读数作废（RC=2）」。但体检只发了 4 次检索，
多出来的包是产品自己的 `providers/base.py` 对 429/5xx 做 HTTP 层重试发出去的（未治项 N2）——
把产品的行为算到仪器头上，等于让一个"窗口其实够用"的读数被作废掉。

新语义（同一台仪器三种结论不许共用一个码）：
- RC=0 活的源 ≥2 **且**外发 = 每源一次（4 包）⇒ 窗口健康，起跑；
- RC=3 活的源 <2 ⇒ 窗口不健康，别拿一小时的模型调用去换一个会被供给判死的数；
- RC=5 活的源 ≥2 但外发 >4 包 ⇒ **可以起跑**，但 N2 的重试放大在场；不是仪器坏了，
  也不许读成「包数没问题」。

换代前后的真实读数（同一台仪器、间隔 5—25 分钟，见 `docs/evidence/g166_supply_repeat_readings.txt`）：
12:2x 活的源 1、8 包、RC=3（上一版语义，`g165` 就是那一场）；13:3x 活的源 2、6 包；
13:4x 活的源 3、4 包；13:5x 活的源 2、6 包；14:0x 换代后 活的源 3、6 包、**RC=5**。
⇒ 两件事同时成立：**供给是分钟级在抖的**（同一天里活的源在 1—3 之间来回），
而**包数放大稳定复现**（5 次读数里 4 次 >4 包）——N2 不是偶发，值得单独治。
