# measure-20260926h：`probe_provider_supply.py`（A/B 起跑前的文献源窗口体检，零模型调用）

为什么需要它：事项二那场 A/B 判「未测」（RC=3）不是因为两臂等价，而是可用对只剩 10/15，
5 对全部损耗在「走到检索轮但两臂都 0 卡」。容器裸日志里数得出 10 次 provider 熔断
（OpenAlex、Semantic Scholar 各自 120→240→480→900s 连击，arXiv 一次 406）
⇒ **可用对分母是供给的函数，不是料的函数**（同一批「首问即放行」的料：上一场 9/9 全可用、这一场 10/15）。
所以以后跑任何"要真检索"的 A/B，先过这一台：**活的源 ≥2 才许起跑**。

判据跑前写死：P1 四源各一条固定查询；P2 「活」= 拿到 ≥1 条（0 条与不可用分开记，轮 96 的口径）；
P3 外呼包数在 **httpx 传输层**数（`AsyncClient.send`），≤4 才算这台体检自己在刷配额；
P4 活的源 <2 ⇒ RC=3「窗口不健康」——它只决定"现在跑不跑"，不改任何预登记判据。

🔴 这台仪器首跑抓到两处，都已改口并留在本目录字节里：
① 判据原先拿产品自己的 `provider_stats()['calls']` 数包，实测四包都发出去它仍报 0
   ⇒ 那条线**恒真**（等于没写）。换成 httpx 传输层挂表，才有下面的发现。
② 挂表后立刻量到：**一次失败的 `search()` 实发 3 包**（`base.get_json` 对 429 退避重试）。
   四源体检 = **8 包**（crossref 1、arxiv 1、openalex 3、s2 3），并为此白睡约 3×1.5s 的退避。
   ⇒ P3 当场把本场判成 RC=2（"体检自己在刷配额"），这正是它该红的时候红的样子。
   产品含义（未决项，见 `docs/METHOD_BACKLOG.md`）：被限流的源每次检索被敲三包，
   而 OpenAlex 的 429 带的是**日额度**级 Retry-After——越重试越早在当天被关在门外，
   线上表现为"综述没有文献依据"的时间变长。修法方向：429/403/406 一律不 HTTP 层重试，
   交给熔断；5xx 与网络错保留重试。这条改动要单独配前后数（每源包数 3→1）与测试，不塞进本轮。

本场读数（`docs/evidence/g165_provider_supply_window.txt`）：crossref 活（1.6s 回 3 条）、
arXiv 406、OpenAlex 429、Semantic Scholar 429 ⇒ 活的源 1 <2 ⇒ **RC=3，窗口不健康**，
事项二的第二场不在今晚起跑。
