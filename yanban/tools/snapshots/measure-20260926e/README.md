# measure-20260926e：`probe_renumber_replay.py`（事项一的前后数量具，零模型调用）

把 `evidence.renumber_citations` 回放到线上 12 份真报告上，量"报告生成路径接上改指"这一改动
值几 pp。三条不像但关键的做法：

1. **依据池由报告自己反推**：编号 n = 生成当时 `citable_papers` 的位置，所以池子按报告末尾
   「## 引用论文」里 `[[论文：标题]]` 的出现顺序重建，再用标题回查生产库 `papers.paper_json` 取原文。
   任一条对不上 ⇒ 该份整份剔出分母（宁可少样本，不要错位样本）。拿 DB 顺序凑会把 [2] 指向另一篇。
2. **只测正文**：「引用论文」节是程序拼的，它的首"句"是一条论文标题，会被接地尺数成句子
   （轮 106 栽过：g68 那个 11% 的反证率就是这么来的）。
3. **两臂只差改指一步**：臂 A 只跑 mentor 那三道删除闸门，臂 B 跑线上 `clean_report_with_ledger`，
   两边都用**同一把** `grounding_report` ⇒ R5 负控（关掉改指、同文本量两遍必须逐位相同）才有意义。

判据跑前写死在文件头：R0 真调用增量必须 0；R1 DB mtime+size 与 KB .md 数逐位不变；
R2 容器 `report.py` 必须有 `clean_report_with_ledger`（否则读数不属于将跑的 build）；
R3 分母两侧都写；带角标句 <20 ⇒ RC=3 只作定性；R4 主判据 = 合并通过率提升 ≥5pp 且无一份变差；
R5 负控 RC=2；R6 零模型调用直接调容器里那份 `_finalize`（`KB_ROOT` 改指 /tmp，不碰生产知识库），
必须交出 `citations_renumbered=1` 且落盘正文被改指、逐句四元组为 (4,3,0,1)。

本场读数（`docs/evidence/g160_renumber_replay_online.txt`）：12 份报告 / 174 带角标句，
接地 148→160、错号 12→0、真空 14→14，改指 17 处，通过率 **85.1% → 92.0%（+6.9pp）**、
变差 0 份 ⇒ RC=0 达标；负控场两遍逐位相同、+0.0pp ⇒ RC=2；R6 两条场都 ✅。
R7 顺手量了个盲区：正文里角标共 199 处，紧跟句末标点的 **0** 处 ⇒ 这份分布上"角标挂在句号后面
被尺子切成碎片"这件事没有发生（我第一版合成夹具正好写成了那种形状，被 R6 当场判红——
红的是夹具，不是产品，已把期望改成逐句四元组）。
